## What the binder had to learn from the file rather than the docs

1. **The scale sibling replaces `.weight`, it does not append to it** — `attn.wq_a.weight` pairs
   with `attn.wq_a.scale`. The first build assumed `.weight.scale` and failed on layer 0.
2. **Two different scale geometries.** Dense FP8 is a **32x32** grid; routed FP4 is **1x32
   along K only**. Assuming one geometry for both would have silently mis-scaled every expert.
3. **`compressor.wgate` exists on layers 2, 8, 14 but not 20.** Not an omission in the
   checkpoint: `Compressor.__init__` only builds a gate when it actually pools, and layer 20's
   `compress_ratio` is 1. The binder derives `has_compressor_gate = is_kv_source && ratio > 1`
   and *forbids* the tensor elsewhere, so a future checkpoint that disagreed would fail loudly.
4. **`indexer.wk` / `k_norm` live only on the four KV-source layers**, not on all eight index
   sources — the indexer's K is derived from the shared compressed latent, so it exists only
   where that latent is produced.

## Correction to `03_ARCH_FROM_THE_CODE`

That doc says `wo_a` is bf16, citing the reference's `dtype=torch.bfloat16` argument. **In the
shipped checkpoint `wo_a` is F8_E4M3 with a 32x32 scale grid** (`[8192, 4096]` + `[256, 128]`).
The reference's `dtype=` describes the unquantised model; the fp8 checkpoint overrides it. The
binder uses the file.

## Where this leaves the port

Everything now has a name, a shape, and a byte count. Remaining, in order:

1. **Device upload + expert tiering.** 268.95 GiB of routed experts against 59.6 GiB VRAM +
   ~215 GiB RAM. Everything else in the text path is 8.87 GiB and fits in one card.
2. **Dense FP8 dequant on device** (new; V4's dense is Q8_0/BF16).
3. **Forward pass**, forking `deepseek4`: mHC (`ds4_sinkhorn4` already does hc_mult=4),
   latent attention at head_dim 512 with one KV head, window+compressed KV, the indexer,
   sqrtsoftplus/noaux_tc routing, MXFP4 experts (existing kernels).
4. **Engram** at layers 1 and 14 — not deferrable, it adds into the residual stream.
5. NVMe expert tier; then vision and DSpark, both deferrable.
